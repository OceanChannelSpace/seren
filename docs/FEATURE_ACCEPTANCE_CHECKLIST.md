# Feature Acceptance Checklist — "Flourishing by Design" Pre-Ship Test

**Run this before any feature ships — new screens, flows, copy changes,
matching changes, AI behavior changes, notifications, events.**

A feature that cannot pass this test is not ready. **If it cannot pass, do
not build it yet** — redesign with limits, friction, consent, human
stewardship, and off-app completion, or set it aside.

Fill it out in order. Be honest; "unsure" is a finding, not a failure.

### 0. Does it fit inside the Constitution — and nothing else?

Before anything else: the SEREN Constitution (§6, supremacy clause,
2026-10-10) is supreme over every framework SEREN draws on — Probert's
research, Kevin's braid guidance, Bailey's ethical architecture, the Orpheus
Model, any future advisor's work. If the feature imports an idea that
conflicts with the Constitution's guardrails, or simply does not fit
within them, it does not ship — no matter how good the source is.
Frameworks serve the connector; they never redefine it. If "unsure," the
feature waits for host review.

## The 10 questions

### 1. What human capacity does this strengthen?

Name it plainly: presence, discernment, connection, reflection, courage,
clarity, compassion, capability. If the honest answer is "it keeps them in
the app," it fails here.

### 2. What real-world outcome should it enable?

Describe the concrete off-screen result: a conversation had, a gathering
attended, a collaboration started, a practice begun, a boundary set. End
the flow with the standing question: *"What would you like to bring into
your real life in the next 24 hours?"*

### 3. What is the most likely harmful or compulsive use pattern?

Imagine the feature misused — by design, by habit, or by a bad actor.
Compulsive checking? Passive scrolling? Endless AI conversation instead of
human contact? Performance of spirituality for approval? Write the worst
plausible pattern down.

### 4. What consent, clarity, and friction protect the user?

List the concrete safeguards: granular opt-in, mutual consent, "not now" /
"pause" paths, confirmations before irreversible sharing, cooling periods,
humble labeling of AI output. Every safeguard in Q3's pattern needs a
matching protection here — or the feature waits.

### 5. Does it preserve agency?

Can the user understand what's happening, say no without penalty, and
choose a human path instead of an AI one? Does the copy position the AI as
a reflection partner — never a guru, oracle, or therapist?

### 6. Could it cause false certainty, dependency, oversharing, coercion, or isolation?

Walk through each risk:
- **False certainty:** does anything imply the system knows what's true,
  fated, or best for the user?
- **Dependency:** does value require sustained use, or does it work when
  used lightly?
- **Oversharing:** does it invite, reward, or require disclosure beyond
  what connection needs?
- **Coercion:** could it pressure, guilt, or manipulate — by copy, by
  mechanics, by social dynamics?
- **Isolation:** could it pull the user away from outside relationships,
  care, or critical thinking?

### 7. Can the user pause, reject, change, or leave easily?

Test the exits: pause matching, decline without shaming copy, change
consents, delete data, leave the community. Every exit must be immediate,
obvious, and penalty-free. If leaving costs something (lost history,
social pressure, dark patterns), the feature is not done.

### 8. Would the user still benefit using it less?

The anti-engagement test. If the feature's value collapses when the user
opens the app less often, it's an engagement feature wearing a
flourishing costume. Redesign until light, occasional use still delivers
the full benefit.

### 9. How will we measure a meaningful positive outcome?

Name the real-world metric — not screen time, not DAU. Examples: %
reporting a meaningful consent-based real-world action in 30 days; %
introductions leading to mutually positive conversation/gathering/
collaboration; % reporting increased connection, clarity, agency,
belonging; safety incident rates and resolution times; % feeling able to
pause/leave freely; % reporting the AI felt appropriately humble.

### 10. Does it bring people closer to real life — or further into the app?

The final gut check. Trace the user's path: does this end at a human being,
a real conversation, a lived experience — or at another screen? The screen
is a starting line, never the destination.
